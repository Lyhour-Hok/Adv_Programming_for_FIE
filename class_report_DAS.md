PEP and debugging are different. They are not parts of a program, but skills for writing good code: PEP 8 keeps code clean and easy to read, and debugging helps us find and fix errors when the code does not work.

## Phase 2: PEP and Debugging

| Concept | What it is used for | Status |
| --- | --- | --- |
| PEP | Python Enhancement Proposal; PEP 8 is the style guide for writing clean, readable Python code |  |
| Debugging | Finding and fixing errors (bugs) in a program |  |

**PEP 8** is the official style guide for writing Python code. PEP stands for Python Enhancement Proposal. PEP 8 gives rules that make code clean and easy for everyone to read:

- Variables and functions use lowercase words joined by underscores (snake\_case).
- Constants use all capital letters.
- Classes start each word with a capital letter.
- Code is indented with 4 spaces, and lines stay short.

**Debugging** is the process of finding and fixing errors (bugs) in a program. There are three main kinds of errors:

- Syntax errors: the code breaks Python's grammar rules, so it cannot run.
- Runtime errors: the code starts running but stops with an error message.
- Logic errors: the code runs but gives the wrong result.

To debug, we read the error message carefully, print values to check them, and use a debugger to pause the program at breakpoints and run it step by step.
